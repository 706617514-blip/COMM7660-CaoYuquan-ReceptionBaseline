# 主角与装备美术方向简报

按 `create-game-assets` 技能流程编写（步骤 1–4：勘察 → 锁定技术参数 → 定义视觉语言 → 建素材清单）。
与 `boss-art-brief.md` 配套：Boss 简报定的是**敌人**，本简报定的是**主角与其 28 件装备**。

**当前状态：规格已冻结，等待生成后端。**
本机无任何可达的图像生成通道（见 §7 探测记录）。本简报与配套的
`docs/art/prompts/protagonist-prompts.json` 一旦有可用后端即可直接批量出图。

---

## 1. 勘察现有画面（步骤 1）

**不重新设计美术方向，沿用现有语言。** 技能明确要求：
*"Preserve a coherent existing direction unless the user asks for a redesign."*

### 1.1 现实与早期简报的偏差（必须先说清楚）

`boss-art-brief.md` 写于「本机无图像生成能力」时期，它描述的是一个
**藤蔓触手怪**（6 条触手、240×220、上宽下窄的树桩）。但仓库里
`game/assets/` 实际落地的六张 Boss 图**不是**那个形态：

| | 简报设想 | 实际资产 |
|---|---|---|
| 形态 | 藤蔓触手团块 | **人形树精**（直立、有头有四肢、双足站地） |
| 尺寸 | 240×220 | 191×321 / 193×407 / 196×403 |
| 视图 | 侧视单帧 | **左 / 右两视图**（已验证） |

**裁决：以实际资产为准，不以简报设想为准。** 技能步骤 1 要求
"inspect before inventing"——重建议的是**画面上真实存在**的东西。
本案的主角必须与**落地的 Boss** 同族，而不是与一份未兑现的简报同族。

### 1.2 现有元素实测规格

| 现有元素 | 实测规格 | 来源 |
|---|---|---|
| 画布 | 960×600，地面基线 y=515 | `game/config.js` `GROUND_Y` |
| 景深带 | z ∈ [0, 210] | `game/config.js` `FIELD_D` |
| **主角（当前）** | **40×60 px，纯 `Graphics` 几何占位**（蓝灰方块人），无位图 | `game/app.js:313` `generateTexture('hero', 40, 60)` |
| 主角装备层 | 每件装备一张 40×60 贴图，**只画右视图**，左视图靠 `setFlipX` 镜像 | `game/app.js` `equipLayer()` / `EQUIP_LAYER_ORDER` |
| 装备层序 | 背 → 躯干 → 脚 → 头 → 武器 | `game/app.js` |
| 锚点 | 底部中心（origin 0.5, 1），贴地绘制 | 全项目一致 |
| Boss 位图 | 191×321 / 193×407 / 196×403，RGBA | `game/assets/` |
| 描边惯例 | 深色底 → 主体 → 受光面 → 高光（**四层**） | 全项目一致 |

**最关键的发现：主角从来没有生产级美术。**
它是 `Graphics` 画出来的 40×60 几何占位——Boss 拿到了位图，主角没有。
这正是本次任务的真实缺口。

### 1.3 从实际资产提取的锁色（程序化，非目测）

对 `boss_*_right.png` 的 alpha>128 像素做直方图，取占比最高的色：

| 难度 | 墨线（最暗） | 主体 | 受光面 |
|---|---|---|---|
| normal | `#1a1611` | `#393126` | `#655a49` |
| hard | `#0e0c06` | `#4d4f1e` | `#646130` |
| hell | `#0f0504` | `#4d2f2a` | `#653d36` |

三档构成一条清晰的色相推进：**土褐 → 橄榄绿 → 血红**。
主角取 **normal 档族**（玩家是常量，不该随难度换皮），并在
`#1a1611`–`#8a7d68` 之间建立完整的五级明度阶梯。

## 2. 技术参数（步骤 2）

| 参数 | 值 | 理由 |
|---|---|---|
| 视图 | **4 向：右 / 左 / 背 / 四分之三** | 用户明确要求"角色会转身，要做多个对应视图" |
| 原生尺寸 | **96×144 px**（主角本体） | 主角是 40×60 的可玩角色；2.4× 出图后降到 1× 更清晰。Boss 是 191×321，主角约为其 1/2 高，符合"人 vs 巨物"的体型差 |
| 装备层画布 | **96×144**，与主角共用同一坐标系 | 与现有 40×60 层一致的做法，只是分辨率提高 |
| 透明度 | **必须带 alpha 通道** | 否则盖住地面 |
| 锚点 | **底部中心**（origin 0.5, 1） | 与其他实体一致 |
| 调色板 | **≤ 32 色** | 与简报和现有敌人一致 |
| 光源 | **统一自左上打光** | 全项目一致，不可逐图变化 |
| 输出格式 | PNG-24 with alpha | 与 Phaser 加载方式一致 |
| 帧数 | **静态单帧 + 程序化动态** | 沿用 Boss 的做法：姿态由 `bosspose` 式的纯函数驱动 |

**为什么不做逐帧动画：** 与 Boss 简报同一条理由——逐帧需要 8–12 张图/动作，
而主角有 6 组动作 × 4 视图，逐帧会膨胀到 200+ 张。静态单帧 + 程序化姿态
（已有 `bosspose.js` 的成熟先例）能用 1/10 的图量拿到同样的观感。

## 3. 视觉语言（步骤 3）

### 3.1 形状语言

- **主体**：矮壮、敦实。宽肩、短腿、重心低——与 Boss 的"高瘦树精"形成对比，
  让玩家一眼分清"谁是可控角色"
- **材质**：粗布 + 旧皮革 + 少量铁片。**不做华丽奇幻铠甲**
- **轮廓优先**：在 96px 高下必须能看出"这是一个拿剑举盾的人"

### 3.2 轮廓优先级（技能要求：定义"在游戏尺寸下必须存活的特征"）

| 优先级 | 特征 | 在 1×（96px）下是否可见 |
|---|---|---|
| 1 | 圆盾的**圆形剪影** | **必须可见** —— 这是主角最强的识别符号 |
| 2 | 直剑的**斜向直线** | **必须可见** |
| 3 | 头部（有盔/无盔的差异） | **必须可见** |
| 4 | 肩带与腰带的分割线 | 1× 下可省略 |
| 5 | 布料的褶皱纹理 | 仅 3× 下需要 |

### 3.3 配色角色

| 角色 | 色值 | 用途 |
|---|---|---|
| 墨线 | `#1a1611` | 轮廓，四层惯例的最底层 |
| 暗部 | `#251f18` | 阴影面 |
| 主体 | `#393126` | 与 Boss normal 档**同色** —— 强化"同族"关联 |
| 受光 | `#655a49` | 左上方受光面 |
| 高光 | `#8a7d68` | 金属边缘与盾面最高点 |
| **余烬** | `#ff7a3c` | **唯一暖色**，只用于眼睛（受伤/暴击时由代码提亮） |
| 皮肤 | `#6b5a48` | 裸露面部与手 |

**关键：余烬橙在主角身上只出现在眼睛。** Boss 简报已把暖色定为
"前摇预警"这一唯一语义；主角若在身上用暖色，会污染玩家对预警信号的判读。

### 3.4 光源与边缘处理

- 光源固定**左上**，与 Boss 一致
- 边缘：**硬边木刻感**——细密排线做明暗，禁止平滑渐变与喷枪过渡
- 描边：深色 `#1a1611`，宽度在 96px 下约 1.5px

| 背部 back | 短披风 / 长斗篷 / 符文披风 / 翼形斗篷 | 血滴护符 / 余烬披风 |

- **基础装备靠档位递增的"量感"区分**（tier 0→3 越来越厚实/精良）
- **特效装备靠"机制可视化"区分**（雷鸣 = 电弧、熔火 = 灼痕、荆棘 = 尖刺、相位 = 半透明）

## 5. 生成提示词

完整、逐条、可直接执行的提示词在
`docs/art/prompts/protagonist-prompts.json`（机器可读，含每条的
view / slot / tier / 文件名 / 提示词正文）。
提示词按 `create-game-assets` 的 prompt blocks 结构组织：

```text
ROLE/PURPOSE: production asset for [gameplay role]
SUBJECT:      [specific object/character and action]
VIEW:         [orthographic direction], [facing]
ART DIRECTION:[shape language], [palette roles], [materials], [edge treatment]
GAME-SCALE READ: [silhouette and focal details that must survive at WxH]
TECHNICAL OUTPUT: [dimensions], [transparent], [frame count]
LOCKS:        preserve [identity, proportions, palette, costume, lighting, line weight]
EXCLUDE:      text, labels, frames, scenery, duplicate objects, cropped edges, signatures
```

**一致性纪律（技能步骤 6）：** 先出主角本体 4 视图作为**批准的视觉目标**，
之后每一张装备/动作图都以它为 edit/reference 输入，而不是各写一段独立提示词——
独立提示词必然风格漂移。

## 6. 验收标准（步骤 9）

生成后**必须**通过机器检查：

```bash
python scripts/asset_report.py <file>.png \
  --expect-size 96x144 --require-alpha --max-colors 32 --json
```

`--require-alpha` 会拒绝"整图不透明"的文件——那是背景没抠干净的标志。
提示词里写 "transparent" **不等于**真的透明，必须验。

并人工核对：

- [ ] `build_preview_sheet.py` 出一张 contact sheet，**在棋盘格上看**
- [ ] 缩到 **1×（96px 高）** 时，圆盾与剑的剪影仍可辨认
- [ ] 与 `boss_normal_right.png` 并排时，**色调属于同一族**
- [ ] 余烬橙**只**出现在眼睛
- [ ] 放进真实游戏背景（`docs/screenshots/run.png` 的地面）看，不是看白底
- [ ] 四视图之间**身份不漂移**：同一件装备在四个角度是同一件东西

## 7. 生成后端探测记录（2026-11-13）

| 通道 | 结果 |
|---|---|
| DSH `generate_image`（provider=google） | **失败**：`requires the Google Gemini API key` |
| DSH 凭据库 `~/.dsh` `.credentials.yaml` | 仅含 `DEEPSEEK_API_KEY` / `OPENROUTER_API_KEY`，**无任何图像通道密钥** |
| `gpt-image-playground` 插件 | `profiles.json` 里 `apiKey` **为空字符串**（len=0）；`images/` 目录空 |
| OpenRouter 图像模型 | 密钥**有效**（435 个模型可见），但所有图像输出模型返回 **403 区域限制**：`This model is not available in your region`。测试了 8 个候选（`google/gemini-4-carbon`、`google/gemini-omni-1.2-flash` 等）——其中 2 个 403，5 个明确不支持图像输出模态 |
| Codex `imagegen` 技能 | 依赖 Codex 内置 `image_gen` 工具或 `OPENAI_API_KEY`，**两者本机都没有** |
| ComfyUI（本地） | 未安装，`127.0.0.1:8188` 无响应 |
| Blender（本地渲染路径） | 未安装 |
| AIMC 平台 | HTTP 200 可达，但**只支持 SSO 登录**；agent 不应代为登录（需账号凭据，违反课程材料使用规定，见 `aimc-platform-probe.md`） |
| Pillow | 12.3.0 **可用** —— 归一化 / 校验 / 拼图这三步现在就能跑 |

**结论：瓶颈是密钥，不是流程。** 规格、提示词、归一化、验收全部就绪；
加任意一个图像密钥（Gemini / OpenAI / 或解除 OpenRouter 区域限制）即可批量出图。

## 第 2 步：试听音效

**为什么要做**：17 个音效是我用代码合成的（没有下载任何音频文件），我**听不到声音**，只能看波形参数。好不好听、吵不吵、像不像，只能靠你的耳朵。

**怎么听**：

1. 打开游戏（本地 <http://127.0.0.1:8788/> 或上线后的正式网址都行）
2. **先把音量调到 30 左右**（页面上有权重滑块）
3. 依次触发这 17 个音：

| 音效 | 怎么触发 | 我做的意图 |
|---|---|---|
| `slash` 挥砍 | 按 J 普通攻击 | 刀刃破风，高频先起快速衰减 |
| `hit` 命中 | 打中敌人 | 低频下坠，身体能感觉到的那一下 |
| `crit` 暴击 | 打出暴击 | 上扬泛音，比普通命中更"亮"更"重" |
| `hurt` 自己受伤 | 被敌人打到 | 方波闷哼，压住高频（不能比命中还亮） |
| `coin` 铜币 | 捡到铜币 | 两枚先后落下，干净的正弦 |
| `seed` 种子 | 捡到种子 | 比铜币更高更薄 |
| `dropNew` 新装备 | 掉落一件没见过的装备 | 三声部，有"升级感" |
| `dropDup` 重复装备 | 掉落重复装备 | 两声部，刻意做得比 `dropNew` 平淡 |
| `potion` 喝药水 | 按 1/2/3 | 吞咽感 |
| `skill` 技能 | 按 U/I/O/L | 技能释放 |
| `special` 装备特技 | 按 V | 装备自带技能，更特别 |
| `upgrade` 强化 | 铁匠铺/兵器架点升级 | 钱花出去的"成长感" |
| `sell` 出售 | 背包里右键卖装备 | 收钱 |
| `bagOpen` 开关背包 | 按 Tab | 面板开合 |
| `wave` 过一波 | 清完一波怪 | 阶段性胜利 |
| `boss` Boss 出场 | Boss 关开始 | 压迫感 |
| `death` 死亡 | 血量归零 | 失败 |

**怎么算成功**：你能说出「哪个太吵 / 哪个听不见 / 哪个和另一个分不清 / 哪个不像」。

**怎么告诉我**：直接说就行，比如「`crit` 太刺耳，`dropDup` 完全听不出来」。我会去调 `game/config.js` 里 `AUDIO.sfx` 的波形参数。

**已知的一个隐患**：连击时三段攻击在同一帧可能叠三次 `slash`，我在代码里加了 25 毫秒的节流防止爆音。如果你听到"啪"的一声糊在一起，告诉我，我把节流调大。

## 第 3 步：用户测试（最重要，也最花时间）

### 3.1 先发招募消息

打开 `evaluation/recruitment-message.md`，里面有一段英文私信模板。**要做的**：

1. 复制那段 `> Subject: 15 minutes...` 开头的消息
2. 把三个方括号替换掉：
   - `[name]` → 对方名字
   - `[you've shipped something on Steam / you work on games / you've been through a launch]` → 三选一，选最贴合对方的
   - `[dates]` 和 `[date options]` → 你方便的几个日期时间
3. **一条一条单独发**给对方，不要群发，也不要发到群里

**找谁**：做过游戏的人、发过项目的同学。**不要找已经看过这个工具的人。**

**目标**：发 12–15 条，最后约到 5–8 个人。

### 3.2 每一场怎么做

**跑之前**（每场都做）：

1. 打开 `evaluation/facilitator-script.md`，从头读一遍
2. 用**全新的浏览器标签页**打开网址
3. 把 `evaluation/observation-sheet.csv` 打开（用 Excel 或 WPS）
4. 给对方分配代号 P1、P2……**不要记真名**
5. 读一遍 `evaluation/consent-and-information.md`（要对照学校伦理要求）
6. 提醒自己：**不要演示，不要解释界面**

**跑的时候**：严格照着 `facilitator-script.md` 念开场白，然后按 Task 1 → 2 → 3 → Question 4 → 5 → 6 走。**多听少说。**

**跑完立刻**：往 `observation-sheet.csv` 加一行，趁记忆还热。表头 20 列，含义在表里。**不要把猜测写成结论，只记发生的事情。**

### 3.3 判定标准（已经冻结，不能改）

| 指标 | 意思 | 及格线 |
|---|---|---|
| 完成率 | 成功看到百分位的场次 ÷ 总场次 | ≥ 70% |
| 理解率 | 正确回答「换成解谜品类，百分位会变吗」→ **不会** | ≥ 60% |
| 发现列表使用 | 至少点开一个 Steam 商店链接的人 | ≥ 50% |
| 报错 | 出现报错/不支持输入/越界数字的场次 | ≤ 5% |

**报告格式**：用「7 人里 5 人」这种计数写法，不要只写百分比。

### 3.4 什么情况这场作废

- 参与者之前看过这个工具
- 你在他们自己试之前就解释了某个控件干嘛
- 你告诉他们"正确答案"，或者对错误答案有反应
- 你没当场记，第二天凭记忆补的

**作废一场是诚实的。** 别硬凑。

### 3.5 绝对不要做的事

`AGENTS.md` 写得很清楚，我也不会帮你做：

> 空白行是诚实的。一行参与者没产生的记录，是对作业条款的直接违反。

**永远不要为了凑数编一行。** 如果截止时只有 3 个人跑了，那就如实写 3 个人，然后在报告里说明为什么没跑满。空着比编好。

## 第 5 步：Phase 2 独立验证工作表

**为什么要做**：作业要求「用另一种方法独立重算几个数字」。`records/independent-verification.md` 是 **Phase 1 的**，已做完（2026-10-13）。Phase 2 没有对应文件。

**关键点**：不能只是把分析脚本再跑一遍——脚本有 bug 的话会把自己的 bug 复现出来。必须**手工**从原始计数重算。

**怎么做**（大概 30 分钟）：

1. 复制 `records/independent-verification.md` 的结构，新建一个 Phase 2 的
2. 挑 3–5 个产品侧的数字，用原始数据手算，跟脚本输出对比：
   - 参考分布里的百分位边界值（`analysis/build_product_data.py` 产出）
   - 玩家初始血量 70、伤害 12 这类基础值的来源
   - 装备稀有度分档（tier 0–4）的件数
   - 背包卖价公式：`floor(0.5 × (基础价 + 已投入升级费))`，手算几档对照
3. 记录每个数字：你的手算值、脚本值、差异、差异原因
4. 签上名字和日期

**注意**：有分歧就如实记下来，**不要为了"看起来一致"去改你的手算值**。Phase 1 那份就记录了一个真实分歧（sd 0.1241 vs 0.1245，ddof 取法不同），那才是正确做法。
